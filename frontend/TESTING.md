# تشغيل اختبارات Frontend

## الأوامر المستقلة

```sh
npm test                 # React فقط، كما كان سابقًا
npm run test             # الأمر نفسه: React فقط
npm run test:e2e         # جميع ملفات Playwright بالمشغّل الجديد
npm run test:runner      # فحوص المشغّل نفسه، دون قاعدة بيانات
npm run test:all         # اختياري: React ثم فحوص المشغّل ثم Playwright
```

يبقى الأمر الافتراضي `test` خاصًا بـReact. الأمر الإضافي `test:react` اسم بديل له.
يرجع `test:e2e` فشلًا إذا فشل أي ملف أو إعداد خادمه أو نقص تقريره.
يرجع `test:all` فشلًا إذا فشلت أي مرحلة ولا يُستدعى تلقائيًا من `test`.

## المتطلبات

- Node.js 24 و`npm ci` داخل `frontend` و`backend` المجاور له.
- Backend الذي يدعم عقود الصور والمشرف والنتائج الشخصية. مرجع التكامل المختبر:
  `a7624dea7ffb6a9b30130f064ec36b2ce31fc07c`.
- قاعدة PostgreSQL 16 مخصصة للاختبار، مع متغير `TEST_DATABASE_URL` واسم ينتهي بـ`_test`.
  لا يستخدم المشغّل `DATABASE_URL` بديلًا، ولا يقرأ بيانات قاعدة المشروع.
- متصفح Chromium وإضافاته اللازمة لـPlaywright:

```sh
npx playwright install --with-deps chromium
```

يمكن استخدام صورة Docker المطابقة لإصدار Playwright المثبت بدل تثبيت المتصفح محليًا.
لا تثبّت الاختبارات حزمًا أو متصفحًا تلقائيًا عند التشغيل.

مثال إعداد قاعدة مؤقتة على جهاز التطوير، دون استخدام قاعدة المشروع:

```sh
docker run --rm -d --name mezyad-browser-tests \
  -e POSTGRES_USER=review \
  -e POSTGRES_PASSWORD=local-test-only \
  -e POSTGRES_DB=mezyad_browser_test \
  -p 127.0.0.1:55432:5432 postgres:16

# انتظر pg_isready قبل التشغيل.
export TEST_DATABASE_URL=postgresql://review:local-test-only@127.0.0.1:55432/mezyad_browser_test
npm run test:e2e

# بعد الانتهاء، احذف بيئة الاختبار التي أنشأتها فقط.
docker stop mezyad-browser-tests
```

كلمة المرور في المثال بيانات اختبار محلية فقط. اسم القاعدة المقصود لا يحميك من
اختيار خادم حقيقي بالخطأ؛ استخدم حاوية مخصصة فارغة. يجب أن يكون المنفذان المحليان
`44017` و`44018` غير مشغولين قبل الاختبار.

## العزل وتجميع النتائج

`frontend/scripts/run-browser-tests.mjs` يكتشف الملفات كلها ويرتّبها ويشغّلها بالتتابع.
لكل ملف عملية Playwright جديدة، وخادم Backend جديد، ومخطط PostgreSQL عشوائي جديد،
ومجلد رفع صور مؤقت. يتوقف الخادم بعد الملف، ويتحقق المشغّل من إزالة مخططه.
بذلك تبقى حدود حماية Backend الفعلية كما هي، ولا تتراكم محاولات تسجيل الدخول
الاصطناعية من ملفات غير مرتبطة داخل الخادم نفسه.

- لا يعاد استخدام خادم قائم أو تقارير تشغيل سابق.
- تُستخدم جلسات إعداد حقيقية مخزنة مؤقتًا داخل مخطط الملف فقط.
- `--forbid-only` يمنع اعتماد مجموعة جزئية بالخطأ، والإعادات التلقائية معطلة.
- فشل العملية أو إعداد الخادم، أو غياب JSON، أو نتيجة فارغة، أو اختبار فاشل أو متجاوز
  أو flaky يجعل ملخص المجموعة فاشلًا، حتى لو نجح آخر ملف.
- البيانات والأهلية البنكية الاصطناعية تخص الاختبار فقط؛ البنك الحقيقي مؤجل، وحالة
  `BANK_SANDBOX_UNAVAILABLE` تختبر دون ادعاء نجاح التكامل.

تُكتب النتائج افتراضيًا داخل مجلد جديد وفريد تحت مجلد النظام المؤقت
`mezyad-browser-results`. يطبع الأمر مسار `results.json` في النهاية.
كل ملف له `report.json` ولقطاته في مجلده. الملخص يحتوي الأعداد والنتيجة النهائية
ومسارات تقارير التشغيل الحالي، وأسماء المخططات وتأكيد إزالتها.

يمكن تخصيص مواقع التقارير دون إضافتها إلى المشروع:

```sh
E2E_RESULTS_DIR=/tmp/mezyad-review-results \
E2E_JSON_FILE=/tmp/mezyad-review-summary.json \
npm run test:e2e
```

لتحديد خيارات Vitest استخدم `npm run test:react -- ...`. مشغّل `test:e2e` يشغّل جميع
الملفات ولا يقبل مرشحات؛ استخدم Playwright مباشرة لتشخيص جزء محدد، ولا تعتبر ذلك
تشغيلًا كاملًا. لا تُرفع النتائج أو مجلدات الصور المؤقتة إلى GitHub.

## ملاحظة CI

لم يتغير دور `npm test` في CI: يشغّل React فقط. لم يُعدّل Workflow.
تشغيل `test:e2e` أو `test:all` يدويًا أو في CI يحتاج Backend المتوافق وPostgreSQL
وChromium كما هو موضح أعلاه. نجاح React وحده لا يثبت التكامل في المتصفح.
