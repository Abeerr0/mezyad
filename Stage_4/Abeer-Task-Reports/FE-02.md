# Create the login page (FE-02)

**Status** Done

## What I handled

I handled the email and password form, the sign-in request, session storage, and the return to the requested page. I also connected the existing email verification dialog to the unverified-account response.

## Frontend files in flow order

1. `frontend/src/app/App.jsx` — Mounts the login route and passes its query parameters.
2. `frontend/src/features/auth/pages/Login/Login.jsx` — Owns the form, submit state, and redirect.
3. `frontend/src/features/account/components/account-components.jsx` — Provides the authentication layout and protected-page login link.
4. `frontend/src/shared/ui/PasswordField.jsx` — Renders the shared password control.
5. `frontend/src/features/account/hooks/useWorkspace.js` — Starts and restores the user session.
6. `frontend/src/shared/api/client.js` — Sends the HTTP request and maps API errors.
7. `frontend/src/features/auth/components/AccountVerification.jsx` — Handles code verification for an unverified account.
8. `frontend/src/shared/styles/global.css` — Adapts the authentication layout to small screens.

## Implementation

### 1. Read the route and show the form

The login page can prefill the email from the URL. It checks `next` against an allowlist of internal routes and uses `/activity` when there is no match. The form requires an email and password, and uses the shared password control and one-column layout on smaller screens. ### 2. Send the credentials

I wired the submit handler to trim and lowercase the email, pass the password to `workspace.login`, and block a second submit while the first request is pending. The workspace sends `POST /auth/login` through the shared API client. ### 3. Store the session and redirect

The workspace accepts the response after checking for a token and user ID. It saves the session in React state and `sessionStorage`, restores it on a refresh in the same tab, and clears it when a protected request returns 401. On success the page clears the password and goes to the selected route. [useWorkspace.js 64–103](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/account/hooks/useWorkspace.js#L64-L103) · [useWorkspace.js 178–190](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/account/hooks/useWorkspace.js#L178-L190) · [Login.jsx 37–41](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Login/Login.jsx#L37-L41)

### 4. Show failures and recover an unverified account

The API client maps known error codes to messages. The form displays the error with `role="alert"`. If the API returns `EMAIL_NOT_VERIFIED`, the page opens the code dialog, retries sign-in after verification, and then uses the same redirect. [client.js 13–18](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/shared/api/client.js#L13-L18) · [client.js 38–42](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/shared/api/client.js#L38-L42) · [client.js 109–119](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/shared/api/client.js#L109-L119) · [Login.jsx 42–66](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Login/Login.jsx#L42-L66) · [Login.jsx 133–137](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Login/Login.jsx#L133-L137) · [AccountVerification.jsx 95–120](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/components/AccountVerification.jsx#L95-L120)
