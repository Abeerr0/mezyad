# Develop the bid submission flow (FE-12)

**Status** Implemented

## Scope

The bid flow gives the bidder a minimum amount, a review step and a clear result. It keeps the same request ID when the outcome of a send is uncertain.

## Implementation

### 1. Decide if a bid can be entered

The page reads the auction, recent bids and commitment. It permits a new offer only for an active auction with eligible account and commitment, readable data and a valid minimum. The helper converts amounts to integer halalas, using the starting price for the first offer and the current price plus the increment after bids exist. [Bidding.jsx 23–60](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/auctions/pages/Bidding/Bidding.jsx#L23-L60) · [useMarket.js 90–115](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/auctions/hooks/useMarket.js#L90-L115)

### 2. Validate and confirm

The first action checks the amount and opens review. Confirmation checks the current minimum again before sending. A separate in-flight guard blocks rapid repeated events while the request is active. [Bidding.jsx 81–116](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/auctions/pages/Bidding/Bidding.jsx#L81-L116) · [Bidding.jsx 235–306](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/auctions/pages/Bidding/Bidding.jsx#L235-L306)

### 3. Retain the request ID through uncertainty

The page saves the amount and request ID per user and auction before the first network call. An ambiguous result or duplicate response keeps the saved attempt available. Retrying the saved attempt sends the same amount and ID. The API wrapper checks the returned bid ID and amount before success, and the UI clears the form and refreshes the data. ## UI/UX

| Page or component | Frontend file | What the user sees and does |
| --- | --- | --- |
| Bid page | `Bidding.jsx` | See the auction status, latest amount and minimum bid. The entry and review controls reflect current eligibility. |
| Sign-in, summary and recent offers | `auction-components.jsx` | Use a shared sign-in gate, auction summary and bid rows alongside the form. |
| Review and retry | `Bidding.jsx` | Review the amount before sending. If the previous result is uncertain, see the saved amount and the history or retry action. |
| Accepted bid feedback | `useMarket.js`, `InteractionUI.jsx` | Confirm the response matches the amount and show a notice when the API accepts the bid. |
