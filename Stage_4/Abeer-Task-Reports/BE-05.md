# Document backend and database test coverage (BE-05)

## Scope

Record coverage for Abeer’s backend and database work. Separate automated tests defined in this branch from prior integration, manual API and browser results.

## API Contract

| Route or surface | Access and input | Expected success or coverage |
| --- | --- | --- |
| Listing routes | `POST /api/v1/items`, `PATCH /api/v1/items/:id` and listing reads. | Assert validation, ownership, review transitions and image association. |
| Bid route | `POST /api/v1/auctions/:id/bids`. | Assert request identity, acceptance rules, saved price and rollback. |
| Database and session checks | Native PostgreSQL fixture, session routes and setup command. | Assert keys, session expiry and repeatable setup. |

## Implementation

### 1. Separate the test layers

The Node runner includes unit cases for listing fields and images. Database-backed tests use a disposable database URL and generated schema. The fixture uses a temporary upload directory and starts its API on loopback. [package.json 6–12](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/package.json#L6-L12) · [qa-fixtures.js 10–40](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/tests/helpers/qa-fixtures.js#L10-L40)

### 2. Identify the runtime requirement

Run `npm run test:postgres` from `backend` when dependencies and a disposable native PostgreSQL database are available. Set `TEST_DATABASE_URL` to a database whose name ends in `_test`. The PostgreSQL runner checks the engine and emits TAP. Database-backed tests can skip when their test URL is absent. [test-postgres.js 1–31](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/scripts/test-postgres.js#L1-L31) · [qa-fixtures.js 10–19](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/tests/helpers/qa-fixtures.js#L10-L19)

### 3. Map evidence to the tested scenario

Earlier evidence includes listing resubmission, role scope, image uploads and bid acceptance. The deployed end-to-end report separately records test-mode bidding journeys. These records establish those scenarios on their recorded setups; the suite at the reviewed revision was not rerun. [fe13-abeer.txt 4–17](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/Stage_4/evidence/fe13-abeer.txt#L4-L17) · [E2E_Report.md 35–72](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/Stage_4/E2E_Report.md#L35-L72)
