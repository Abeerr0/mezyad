# Resubmit a rejected listing after correction (BE-02)

## Scope

Explain how a seller sees the rejection reason, edits an eligible listing and sends it back to the review queue. The seller’s request updates the listing; the admin review decision is a separate endpoint.

## API Contract

| Route or surface | Access and input | Expected success or coverage |
| --- | --- | --- |
| `GET /api/v1/items/:id` | Signed-in owner or admin. Use the listing UUID. | `200` with the current state, review metadata and image links. |
| `PATCH /api/v1/items/:id` | Signed-in `USER` who owns the rejected item. Send new title and description. Optionally send fields or replacement images. | `200` with `PENDING_REVIEW` and cleared review metadata. |

## Implementation

### 1. Make the reason available

The admin review route checks the role and decision, requires a nonblank reason for rejection and updates only a pending row. Listing reads include the stored review fields, with detail access limited to the owner or admin. [app.js 972–1012](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L972-L1012) · [listings.js 282–295](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L282-L295)

### 2. Lock and validate the rejected row

PATCH authenticates the account and locks the item with `FOR UPDATE`. While holding that lock, it checks that the row exists, belongs to the caller, is rejected and keeps its original category. [app.js 944–960](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L944-L960) · [listings.js 138–183](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L138-L183)

### 3. Reset review and preserve omitted values

The SQL update returns the same item to pending review and nulls the previous decision fields. Omitted category details retain their stored value. When there are no replacement files, the existing image references are left in place. [listings.js 185–196](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L185-L196) · [listings.js 213–236](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L213-L236)

### Review state transitions

| Before | Action | After |
| --- | --- | --- |
| `PENDING_REVIEW` | Admin rejects the item with a reason | `REJECTED`; reason, reviewer and review time are saved. |
| `REJECTED` | Owner sends a valid correction | `PENDING_REVIEW`; reason, reviewer and review time are cleared. |
| `PENDING_REVIEW` or `APPROVED` | Owner tries to resubmit | `409 INVALID_STATE`; no state change. |

## Findings & Follow-up

The listing holds the current review state. Once the seller resubmits, the prior reason is no longer stored on that row. Use DB-06 when discussing the need for a separate review history.
