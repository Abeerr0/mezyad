# Review the database tables against Stage 3 (DB-01)

## Scope

Compare the Stage 3 table inventory with the Stage 4 SQL and record differences.

## Schema & Constraints

| Stage 3 table | SQL keys and constraints | Stage 4 comparison |
| --- | --- | --- |
| `users` | UUID PK, unique email, role CHECK | Base SQL adds `created_at`. Migration 003 adds verification fields. |
| `user_sessions` | UUID PK, unique token hash, user FK | Core fields match. User deletion cascades to sessions. |
| `categories` | UUID PK, unique name | Core fields match. The seed contains five rows. |
| `items` | UUID PK, seller/category/reviewer FKs, status CHECK | Core fields match. Category-specific fields use JSONB. |
| `item_images` | UUID PK, item FK and required URL | Core fields match. Item deletion cascades to image references. |
| `auctions` | UUID PK, unique item FK, price/date/visibility CHECKs | Migration 002 adds the private-code lookup. |
| `private_auction_access` | Composite PK and two required FKs | Core fields match. Auction deletion removes its grants. |
| `bid_commitments` | UUID PK, auction/user FKs and unique auction/user pair | Migration 004 adds hold amount, release time and a partial unique index. |
| `bids` | UUID PK, required FKs and unique request UUID | Core fields match. The unique auction/bid pair supports the result FK. |
| `auction_results` | Auction PK/FK and composite winner FK | Migration 005 adds winner and seller email timestamps. |
