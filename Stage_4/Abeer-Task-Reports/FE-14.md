# Organize the application shell and navigation (FE-14)

**Status** Implemented with a route-coverage gap

## Scope

The app shell connects the React entry point, shared navigation, hash routes, and account destinations. The administration page is connected to the shell. The review workflow itself belongs to FE-09.

## Implementation

### 1. Mount the application and read routes

The entry point mounts App inside React StrictMode and loads shared styles. App reads the hash and query, listens for changes, and resets the mobile menu when navigation occurs. It updates the title and focuses main content when the page changes. [main.jsx 1–13](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/main.jsx#L1-L13) · [App.jsx 65–92](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/app/App.jsx#L65-L92) · [App.jsx 104–127](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/app/App.jsx#L104-L127)

### 2. Render shared layout and route content

A skip link leads to the focusable content area. The header and footer sit around routed page content, with a notice area and an unknown-page fallback. Common links retain their active state, and the mobile button exposes its expanded state. [App.jsx 255–288](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/app/App.jsx#L255-L288) · [App.jsx 320–365](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/app/App.jsx#L320-L365) · [SiteHeader.jsx 24–42](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/shared/layout/SiteHeader.jsx#L24-L42) · [SiteHeader.jsx 78–85](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/shared/layout/SiteHeader.jsx#L78-L85) · [SiteFooter.jsx 17–29](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/shared/layout/SiteFooter.jsx#L17-L29)

### 3. Apply role-aware navigation

Account navigation resolves the destination based on role, and the header hides the sell shortcut for administrators. The administration route mounts AdminDashboard, which checks the admin role and handles unauthorized responses. The helper also defines a blocked-page list, but App directly mounts the marketplace routes, so hiding an action does not itself cover direct URLs. [SiteHeader.jsx 43–77](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/shared/layout/SiteHeader.jsx#L43-L77) · [admin-navigation.js 3–18](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/admin/admin-navigation.js#L3-L18) · [admin-access.js 1–21](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/admin/admin-access.js#L1-L21) · [App.jsx 307–342](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/app/App.jsx#L307-L342) · [AdminDashboard.jsx 9–33](https://github.com/Abeerr0/mezyad/blob/99b8d4acbbeeea9b678ca555759ef84eb1775b01/frontend/src/features/admin/AdminDashboard.jsx#L9-L33)

## UI/UX

| Page or component | Frontend file | What the user sees and does |
| --- | --- | --- |
| Header and main navigation | `SiteHeader.jsx` | See the active section, use the mobile menu and open the account action or listing shortcut as appropriate. |
| Shared footer | `SiteFooter.jsx` | Find catalog, help, seller guide and private-auction links from any page using the common layout. |
| Account navigation | `account-components.jsx`, `admin-navigation.js` | A signed-in user sees account links appropriate to the role. The account button sends an admin to the administration page. |
| Administration destination | `AdminDashboard.jsx`, `admin-access.js` | The admin view checks the role. A signed-in user outside that role receives a message and a route back to Activity. |
