# Build the account profile page (FE-16)

**Status** Partially implemented on the deployed site

## Scope

The profile displays account information and lets a user choose a character avatar. The source includes name editing and a two-step password change, with a route condition that limits what a real account can reach.

## Implementation

### 1. Show account details and pick an avatar

The profile initializes the selected avatar from workspace and supports both carousel and grid selection. Saving calls chooseAvatar and reports success or a storage problem next to the picker. Workspace stores the option in localStorage under a key that includes the account ID and a mode prefix. [Profile.jsx 23–35](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L23-L35) · [Profile.jsx 124–197](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L124-L197) · [useWorkspace.js 42–63](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/account/hooks/useWorkspace.js#L42-L63)

### 2. Validate edits to the name

The save handler trims the value, checks allowed name characters and bounds, and calls workspace. The real API implementation patches the profile and updates the session with the returned user. The email field stays read-only. [Profile.jsx 38–61](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L38-L61) · [Profile.jsx 207–233](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L207-L233) · [useWorkspace.js 200–218](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/account/hooks/useWorkspace.js#L200-L218)

### 3. Trace the password flow and its reachability

The handler asks the API to verify the current password before accepting a new password and confirmation. On change failure it clears the verification state so the user can restart. Both name editing and password controls are rendered only in demo mode, while verifyPassword rejects demo mode. The deployed profile therefore does not provide a complete editing or password-change flow. [Profile.jsx 63–108](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L63-L108) · [Profile.jsx 235–294](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L235-L294) · [Profile.jsx 369–372](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/profile/pages/Profile/Profile.jsx#L369-L372) · [useWorkspace.js 219–232](https://github.com/Abeerr0/mezyad/blob/206b127eeb10af66ac115684d2531439a1405766/frontend/src/features/account/hooks/useWorkspace.js#L219-L232)

## UI/UX

| Page or component | Frontend file | What the user sees and does |
| --- | --- | --- |
| Account identity | `Profile.jsx` | Read the name and email associated with the signed-in account. |
| Avatar picker | `Profile.jsx`, `Avatar.jsx`, `Profile.css` | Preview character options, move through the list and confirm the selected avatar. |
| Avatar persistence | `useWorkspace.js` | Save the choice for the current account on this browser and reuse it across account views. |
| Account and password controls | `Profile.jsx`, `useWorkspace.js` | The controls exist in source under preview mode. The deployed account view presents read-only account information. |
