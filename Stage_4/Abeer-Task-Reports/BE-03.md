# Validate, store and serve listing images (BE-03)

## Scope

Review the multipart upload path, file validation, managed image storage, database references and temporary delivery links.

## API Contract

| Route or surface | Access and input | Expected success or coverage |
| --- | --- | --- |
| `POST /api/v1/items` with multipart | Signed-in `USER`. Send listing fields and one to six files in `images`. | `201` with saved listing and image links. |
| `PATCH /api/v1/items/:id` with multipart | Owner of a rejected item. Files in `images` are optional. A supplied set replaces the old image references. | `200` with the updated listing and image links. |
| `GET /api/v1/images/:filename` | Use the valid temporary URL returned by a permitted listing query. | Image bytes for a valid managed link; `404 NOT_FOUND` for invalid or expired links. |

## Implementation

### 1. Reject oversized or mismatched uploads early

Multer receives the `images` array in memory. It checks the filename extension and declared MIME, with count and byte limits. Sharp then checks the decoded format, caps decoded pixels and rejects multi-page or unreadable input. [uploads.js 15–65](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/uploads.js#L15-L65) · [app.js 1608–1627](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L1608-L1627)

### 2. Normalize files and coordinate storage with SQL

Sharp rotates and saves the image as JPEG inside 2400 by 2400 without enlargement. Storage uses a generated UUID filename and exclusive writes. The listing transaction writes references and commits before old files are removed. The upload helper removes partially saved files after a processing failure, and the listing handler cleans newly saved files on a failed transaction. [uploads.js 44–102](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/uploads.js#L44-L102) · [listings.js 211–245](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L211-L245)

### 3. Return temporary access links

Managed paths are signed with an HMAC that covers the path and expiry. A link lasts about ten minutes. The image route validates the path, time and signature before serving it. [uploads.js 104–145](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/uploads.js#L104-L145) · [app.js 962–964](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L962-L964)

## Findings & Follow-up

The signing key is created when the process loads, so existing managed links need to be refreshed after a restart. Check this behavior across restarts and, if relevant to deployment, across multiple instances.
