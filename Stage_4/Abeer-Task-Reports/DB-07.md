# Verify clean database setup and seeding (DB-07)

## Scope

Review ordered application of migrations and the seed, including what should happen if setup runs twice.

## Schema & Constraints

| Table or relationship | Key columns | Rule |
| --- | --- | --- |
| Setup | Migrations 001–005 and category seed | One transaction commits after all scripts succeed. |
| Core schema | Ten base tables | Migration 001 creates the tables. Later migrations extend them. |
| `categories` | `name` | Unique seed key. `ON CONFLICT(name) DO NOTHING`. |
| Test schema | Generated schema on disposable PostgreSQL | Scoped search path and cleanup. |

## Implementation

### 1. Apply migrations and seed

Run `npm run db:setup` from `backend` with a disposable database in `DATABASE_URL`. The script applies the base schema, private lookup, verification, hold and email tracking extensions and then the category seed. Errors trigger rollback. [package.json 6–12](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/backend/package.json#L6-L12) · [setup-db.js 5–34](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/backend/scripts/setup-db.js#L5-L34)

### 2. Repeat setup in the same schema

The seed lists five categories. The integration test checks that both runs exit successfully and each leaves ten tables and five categories. [001_categories.sql 1–4](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/database/seeds/001_categories.sql#L1-L4) · [setup-db.test.js 10–35](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/backend/tests/setup-db.test.js#L10-L35)
