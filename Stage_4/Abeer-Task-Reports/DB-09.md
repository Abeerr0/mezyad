# Verify atomic price updates under concurrency (DB-09)

## Scope

Check how competing bids use the current price and how the bid and price updates commit or roll back together.

## Schema & Constraints

| Table or relationship | Key columns | Rule |
| --- | --- | --- |
| `auctions` | `id`, `current_price`, `starting_price`, `minimum_increment` | The transaction locks the auction row. Price fields are `NUMERIC(14,2)`. |
| `bids` | `auction_id`, `amount`, `request_id` | Required auction FK, positive amount, unique request UUID. |
| Write pair | Bid insert and auction price update | Same connection and transaction. A failure rolls back both writes. |

## Implementation

### 1. Lock before reading the current price

The bid endpoint opens a transaction and selects the auction with `FOR UPDATE OF a`. Same-auction submissions acquire the row lock in sequence. [Report.MD 337–341](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/Stage_3/Report.MD#L337-L341) · [app.js 1346–1374](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/backend/src/app.js#L1346-L1374)

### 2. Recheck the minimum and commit

The endpoint checks the database clock and whether a bid already exists, then calculates the minimum in halalas. The accepted path inserts the bid and updates the price before commit. Rejections and failures roll back. [app.js 1498–1546](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/backend/src/app.js#L1498-L1546) · [001_schema.sql 60–66](https://github.com/Abeerr0/mezyad/blob/e4fc24953b75d37f2f905df454fe82ecd1e65103/database/migrations/001_schema.sql#L60-L66)
