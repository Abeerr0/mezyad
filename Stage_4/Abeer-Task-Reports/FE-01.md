# Create the registration page (FE-01)

**Status** Done

## What I handled

I handled the registration form, the email verification screen, and the handoff to the signed-in session. The flow starts on `#/register` and takes the user to the home page after verification and sign-in.

## Frontend files in flow order

1. `frontend/src/app/App.jsx` — Mounts the registration route.
2. `frontend/src/features/auth/pages/Register/Register.jsx` — Owns the form and starts registration.
3. `frontend/src/features/account/components/account-components.jsx` — Provides the shared authentication layout.
4. `frontend/src/shared/ui/PasswordField.jsx` — Renders the password and confirmation inputs.
5. `frontend/src/shared/api/client.js` — Validates input and sends the requests.
6. `frontend/src/features/auth/components/AccountVerification.jsx` — Verifies and resends the email code.
7. `frontend/src/shared/ui/Modal.jsx` — Opens the verification dialog and restores focus on close.
8. `frontend/src/features/account/hooks/useWorkspace.js` — Starts and stores the signed-in session.
9. `frontend/src/shared/styles/global.css` — Adapts the form layout to smaller screens.

## Implementation

### 1. Open and fill out the form

The route passes `workspace` into `Register`. The page keeps the name, email, password, and confirmation in React state. The shared password field has a show/hide button that leaves the form unsubmitted. On narrower screens the shared layout uses a single column. ### 2. Validate and start registration

I checked the trimmed name, email format, password length, and confirmation before posting. The form disables input while the request is busy and shows API errors below the form. The response’s `emailSent` flag controls the first message in the verification dialog and whether the resend countdown starts. [Register.jsx 37–87](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Register/Register.jsx#L37-L87) · [Register.jsx 144–145](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Register/Register.jsx#L144-L145) · [Register.jsx 191–204](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/pages/Register/Register.jsx#L191-L204) · [client.js 151–159](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/shared/api/client.js#L151-L159)

```jsx
const registered = await request(signupPaths.start, {
  method: "POST",
  body: {
    name: name.trim(),
    email: email.trim().toLowerCase(),
    password,
  },
});
setEmailSent(registered.emailSent === true);
```

### 3. Verify the code or request another one

The dialog checks for six digits and sends the email and code to the verification endpoint. It continues only when the API returns `emailVerified: true`. The resend action calls `/auth/resend-code`, resets the countdown to 60 seconds on success, and displays a response error if the request fails. [AccountVerification.jsx 8–11](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/components/AccountVerification.jsx#L8-L11) · [AccountVerification.jsx 63–121](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/components/AccountVerification.jsx#L63-L121) · [AccountVerification.jsx 123–146](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/components/AccountVerification.jsx#L123-L146) · [AccountVerification.jsx 164–230](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auth/components/AccountVerification.jsx#L164-L230) · [Modal.jsx 4–26](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/shared/ui/Modal.jsx#L4-L26)

### 4. Start the session and finish

Once verification succeeds, the completion handler signs in with the same credentials, clears both password fields, closes the dialog, and redirects to the home page. The workspace checks for a token and user ID before storing the session.
