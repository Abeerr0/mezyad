# Create the auction browse page (FE-03)

**Status** Needs Fix

## What I handled

I handled the public auction list, category and status filters, search, sorting, and the link from each auction card to its details. The page also handles loading, request failure, and empty results.

## Frontend files in flow order

1. `frontend/src/app/App.jsx` — Reads the filters, loads the catalog, and opens auction details.
2. `frontend/src/shared/api/client.js` — Makes the catalog requests and reports request failures.
3. `frontend/src/features/auctions/pages/Browse/Browse.jsx` — Renders the filter controls and visible results.
4. `frontend/src/shared/ui/AuctionCard.jsx` — Displays auction data and opens the selected auction.
5. `frontend/src/shared/ui/StatePanel.jsx` — Displays loading and retry states.
6. `frontend/src/shared/hooks/useAutoRefresh.js` — Schedules catalog refreshes while the page is active.
7. `frontend/src/shared/styles/global.css` — Stacks the controls and results on narrow screens.

## Implementation

### 1. Load the public catalog

The app reads `category` and `status` from the browse route. It sends the selected values as `categoryId` and `status`, loads the categories and auction list together, and keeps public auctions for display. It cancels the old request if the route or filters change. ### 2. Apply filters, search, and sort

Category and status controls update the URL so the filter selection can be reopened or shared. Search matches the auction title within the loaded results. The sort options order those results by lowest current price or earliest end time. [Browse.jsx 16–39](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auctions/pages/Browse/Browse.jsx#L16-L39) · [Browse.jsx 58–133](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auctions/pages/Browse/Browse.jsx#L58-L133)

```jsx
function filter(key, value) {
  const params = new URLSearchParams(location.hash.split("?")[1] || "");
  if (value) params.set(key, value);
  else params.delete(key);
  location.hash = "/auctions" + (params.size ? "?" + params.toString() : "");
}
```

## How I handled edge cases

- I kept category and status in the URL because they change the API request. Search and sort stay in the page because they only change the list already loaded. Reloading the same URL restores the category and status filters. [App.jsx 106–116](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/app/App.jsx#L106-L116) · [App.jsx 153–167](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/app/App.jsx#L153-L167) · [Browse.jsx 16–39](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/features/auctions/pages/Browse/Browse.jsx#L16-L39)
- Changing filters cancels the earlier request. The effect also uses an `active` flag before applying results or errors, so an earlier response cannot replace the current filter results after its effect is cleaned up. [App.jsx 129–136](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/app/App.jsx#L129-L136) · [App.jsx 164–205](https://github.com/Abeerr0/mezyad/blob/3241ff4965d733aad039be05f279a97b5c2d71f5/frontend/src/app/App.jsx#L164-L205)
