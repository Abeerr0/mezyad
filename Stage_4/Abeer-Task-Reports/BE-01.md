# Build the listing create and edit API (BE-01)

## Scope

Create a listing for a signed-in user and accept edits to an eligible existing listing. This report covers the shared API entry, field parsing and SQL write. BE-02 covers the rejected-listing state transition in detail.

## API Contract

| Route or surface | Access and input | Expected success or coverage |
| --- | --- | --- |
| `POST /api/v1/items` | Signed-in `USER`. Send `title`, `description` and a category UUID in `categoryId`. Optional `categoryFields` and, with multipart, at least one image. | `201` with `data` containing the saved listing, its review state, `categoryFields` and `images`. |
| `PATCH /api/v1/items/:id` | Signed-in owner of a rejected listing. Send `title` and `description`. Category and fields are optional; any supplied category must match the existing one. | `200` with the saved listing pending review and its image links. |

### Example create request body

Illustrative JSON. Replace the category UUID with the ID of a category in the test database.

```json
{
  "title": "Test listing",
  "description": "Synthetic test asset",
  "categoryId": "00000000-0000-4000-8000-000000000001",
  "categoryFields": {
    "condition": "Good"
  }
}
```

A successful create returns `201` with `data.status` set to `PENDING_REVIEW`. A different seller editing the same existing listing receives `403` with `error.code` set to `FORBIDDEN`. [listings.js 149–159](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L149-L159) · [listings.js 230–236](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L230-L236)

## Implementation

### 1. Authenticate and route the request

Express mounts the listing routes under `/api/v1`. It validates a listing ID, checks the session and user role before upload processing, then delegates to the shared writer. [app.js 931–960](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L931-L960) · [app.js 38–49](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/app.js#L38-L49) · [listings.js 249–253](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L249-L253)

### 2. Validate and normalize fields

The parser requires a nonblank title and description. It trims both values, limits titles to 240 Unicode code points and checks the raw description length against 20,000. A create needs a category UUID. `categoryFields` accepts a JSON object or a multipart string containing an object. Legacy names are accepted, and conflicting values are rejected. [listings.js 57–122](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L57-L122)

### 3. Write and return the record

Create derives `seller_id` from the session. The insert leaves the schema to set `PENDING_REVIEW`. The edit branch locks and checks the target row; the same transaction saves listing data and any image references before returning the record. [listings.js 138–211](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L138-L211) · [listings.js 213–245](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/backend/src/listings.js#L213-L245) · [001_schema.sql 19–27](https://github.com/Abeerr0/mezyad/blob/bbaa86986727558124a3b9ab6de39e203549106b/database/migrations/001_schema.sql#L19-L27)

## Findings & Follow-up

The backend checks the category fields’ object shape. It does not enforce a distinct field schema for each category in this parser. Confirm whether the API should enforce those rules and retain coverage for both accepted field names.
